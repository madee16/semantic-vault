# SemanticVault Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build SemanticVault — a production-grade, portfolio-quality Semantic Search as a Service backend with custom API key security, local Ollama AI integration, explicit embedding model compatibility safeguards, and PostgreSQL pgvector storage.

**Architecture:** A modular FastAPI backend featuring a strict separation between API routing, security/rate-limiting middleware, an abstract Ollama/local AI provider layer, and an asynchronous PostgreSQL + pgvector data access layer. Embedding indexes strictly enforce model version and dimension consistency.

**Tech Stack:** Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2.0 (asyncpg), PostgreSQL 16 + pgvector, PyMuPDF (fitz), Ollama HTTP API (embeddinggemma / nomic-embed-text / llama3.2), Sentence-Transformers fallback, Docker Compose, Pytest.

**Spec:** AI-Engineering-Portfolio/01-SemanticVault requirements from user specification.

## Global Constraints

- **Python Version:** Python 3.12.
- **Hardware Budget:** Optimized for NVIDIA RTX 4050 Laptop GPU (6 GB VRAM) & 16 GB RAM. Only load quantized models sequentially or on-demand; do not run concurrent heavy generative models.
- **Embedding Compatibility Rule:** Explicit model name, version, and dimension tracking per vector index. Inserting or querying with mismatched models or dimensions must raise a strict HTTP 400 validation error. Model migrations must run through an explicit re-embedding routine.
- **Database Requirement:** Production vector similarity search and index verification must run against PostgreSQL + pgvector (via Docker Compose).
- **API Key Security Rule:** Never store plaintext API keys. Keys use format `sv_live_<64-char-hex>`, hashed with SHA-256 + cryptographic salt. Support scopes (`documents:read`, `documents:write`, `search:read`, `admin:keys`), expiration dates, instant revocation, and atomic quota enforcement.

## Review Focus

1. **Embedding Dimension / Model Mismatch:** Querying or inserting document chunks with an embedding generated by a different model or dimension must be blocked before vector distance calculation.
2. **Atomic Quota Race Conditions:** Rapid concurrent requests from the same API key when close to quota limit must not exceed the allowed quota (atomic decrement in SQL).
3. **Expired or Revoked API Key:** Requests with revoked or expired keys must immediately return 401 Unauthorized with timing-safe verification.
4. **Ollama Service Unavailability:** When the local Ollama instance is unreachable, document enrichment and query rewriting must gracefully fall back to defaults, and embeddings must switch to local SentenceTransformers or report a structured service error.
5. **Malformed File / Empty Chunks:** Ingesting empty or corrupted PDF/Markdown files must return clean structured errors (422/400) without crashing the ingestion worker.
